# 01 - state.py Explained

> **File:** `backend/agents/state.py`  
> **Purpose:** Defines the data structure (state) that flows through the entire agent graph.

---

## Imports

```python
from pydantic import BaseModel, Field
```
- **BaseModel**: Pydantic class that gives us data validation, type hints, and easy dict conversion.
- **Field**: Used to set default values for complex types like lists.

---

## The AgentState Class

```python
class AgentState(BaseModel):
```

This is the **single source of truth** for the agent. Every node (observe, plan, think, execute) reads from and writes to this state. Think of it as a shared memory that gets updated as the agent progresses.

---

## Field-by-Field Breakdown

### User Input
```python
user_message: str = ""
```
The original message from the user. Set once, never modified.

**Example:**
```python
user_message = "What are the latest AI trends in 2026?"
```

---

### Observation
```python
observation: str = ""
```
The agent's understanding of the user's request, written in plain English. Set by the `observe_node`.

**Example:**
```python
observation = "The user wants to know about current AI trends in 2026. This is a research task."
```

---

### Plan
```python
plan: list[dict] = Field(default_factory=list)
```
A list of steps the agent will follow. Each step is a plain dict with `task` and `status`.

**Example:**
```python
plan = [
    {"task": "Search for latest AI trends 2026", "status": "completed"},
    {"task": "Search for AI industry reports", "status": "completed"},
    {"task": "Compile findings into summary", "status": "pending"},
    {"task": "Generate response", "status": "pending"},
]
```

---

### Thinking
```python
thinking: str = ""
```
The agent's reasoning about what to do next. Set by the `think_node`.

**Example:**
```python
thinking = "The plan covers the main areas. Search results show strong trends in agentic AI, multimodal models, and AI regulation. Ready to execute."
```

---

### Clarification
```python
clarification_question: str = ""
clarification_options: list[str] = Field(default_factory=list)
```
If the agent needs more info from the user, it stores the question and optional multiple-choice options here.

**Example:**
```python
clarification_question = "Which programming language should I use?"
clarification_options = ["Python", "JavaScript", "TypeScript", "Rust"]
```

---

### Tool Results
```python
tool_results: list[str] = Field(default_factory=list)
```
Results from external tools (like web search). Stored as formatted strings.

**Example:**
```python
tool_results = [
    "Query: AI trends 2026\n1. **Agentic AI** - AI systems that can autonomously...\n2. **Multimodal Models** - ...",
    "Query: AI regulation 2026\n1. **EU AI Act** - New regulations taking effect..."
]
```

---

### Final Response
```python
final_response: str = ""
```
The complete response generated by the `execute_node`. This is what gets sent back to the user.

**Example:**
```python
final_response = "## AI Trends in 2026\n\nHere are the key trends...\n\n1. **Agentic AI** ..."
```

---

### Control Flow Flags
```python
needs_clarification: bool = False
needs_revision: bool = False
skip_to_execute: bool = False
is_complete: bool = False
```

| Flag | When Set to True | Effect |
|------|-----------------|--------|
| `needs_clarification` | Agent can't proceed without user input | Routes to `clarify` node |
| `needs_revision` | Plan needs to be redone after thinking | Routes back to `plan` node |
| `skip_to_execute` | Simple message like "hi" or "hello" | Skips plan/think, goes straight to `execute` |
| `is_complete` | Response has been generated | Signals end of workflow |

---

### History
```python
history: list[dict] = Field(default_factory=list)
```
Previous messages in the conversation. Sent from the frontend.

**Example:**
```python
history = [
    {"role": "user", "content": "What is Python?"},
    {"role": "assistant", "content": "Python is a programming language..."},
]
```

---

### Steps
```python
steps: list[dict] = Field(default_factory=list)
```
Step-by-step details collected during execution. Each node appends its details here. This is what gets displayed in the frontend's expandable "Agent Process" section.

**Example:**
```python
steps = [
    {
        "name": "observe",
        "title": "Observation",
        "detail": "User wants to know about AI trends in 2026.",
        "meta": {"task_type": "research", "has_enough_info": True}
    },
    {
        "name": "plan",
        "title": "Planning",
        "detail": "Created 3 step(s):\n  1. Search for AI trends\n  2. Compile findings\n  3. Generate response",
        "meta": {"plan": [...], "search_queries": ["AI trends 2026"]}
    },
    {
        "name": "think",
        "title": "Reasoning",
        "detail": "Search results look good. Ready to execute.",
        "meta": {"needs_search": False, "needs_revision": False, "needs_clarification": False}
    },
    {
        "name": "execute",
        "title": "Execution",
        "detail": "Response generated successfully.",
        "meta": {"response_length": 1523}
    }
]
```

## Data Flow Diagram

```
User sends "hi"
    ↓
observe_node sets: skip_to_execute=True, observation="hi"
    ↓
route_after_observe sees skip_to_execute=True → goes to execute
    ↓
execute_node sets: final_response="Hello! How can I help?", plan=[{...completed}]
    ↓
State returned to frontend with all fields populated
```
